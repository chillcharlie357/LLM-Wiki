# 提示词工程题套路

牛客 PROMPT1-PROMPT35 这类题，本质不是考“会不会聊天”，而是考能不能把题面规则压成一个稳定的结构化处理器：输入是自然语言，输出必须是可 `JSON.parse` 的固定 JSON。

核心目标只有一个：把题面里的字段、枚举、默认值、公式、优先级、排序和输出 Schema 全部写死，让模型少猜、少补、少发挥。

## 总框架

所有题都可以先套这一层骨架，再把具体规则填进去：

```text
你是严格的数据抽取/规则计算器。请只根据输入文本和下列规则输出 JSON，不要输出解释、Markdown 或多余字段。

处理步骤：
1. 先抽取原始信息，缺失字段按默认值处理。
2. 对枚举字段按题面映射，无法匹配时使用题面要求的 UNKNOWN / 空字符串 / false / null。
3. 对数值字段统一单位、保留位数、取整方式。
4. 多规则冲突时按题面优先级执行，并记录触发规则。
5. 输出必须严格匹配 JSON Schema，字段顺序、字段名、数组排序按要求执行。
```

结尾一定要加硬约束：

```text
最终只输出一个合法 JSON 对象，不要输出 Markdown、解释、推理过程或多余字段。无法判断的内容严格按题目默认值处理。
```

## 六段式速写法

考试时可以直接按下面 6 段拼：

```text
你是严格的 JSON 规则处理器。

【任务】把用户输入转换成指定 JSON。

【字段】逐项列出字段名、类型、默认值。

【映射】列出关键词到枚举的映射，无法匹配怎么处理。

【计算】列出公式、单位换算、排序、取整、保留小数。

【优先级】红线/覆盖规则 > 基础抽取 > 基础计算 > 折扣修正 > 输出校验。

【输出】只输出合法 JSON，不要解释，不要多字段。
```

最重要的不是文采，而是把题面里的“默认值、枚举、优先级、公式、输出格式”完整搬进 Prompt。低通过率题通常不是模型不会算，而是 Prompt 没有把边界条件和冲突规则写死。

## 万能回答模板

```text
你是一个严格的【任务类型】处理器。请根据用户输入，按规则输出指定 JSON。

任务目标：
- 从输入中提取/计算字段，并填入固定 JSON Schema。
- 不要输出解释，不要添加未定义字段。

处理规则：
1. 信息抽取：
   - 识别【字段1】【字段2】【字段3】。
   - 如果字段缺失，按默认值处理：【默认值说明】。

2. 枚举映射：
   - 【关键词A】=>【ENUM_A】
   - 【关键词B】=>【ENUM_B】
   - 无法匹配 =>【UNKNOWN / 空字符串 / null】

3. 数值归一：
   - 单位统一为【单位】。
   - 金额/重量/时间按【换算规则】处理。
   - 小数保留【N】位，取整方式为【向上/向下/四舍五入】。

4. 规则优先级：
   - 先执行红线/拒绝/覆盖规则。
   - 再执行基础计算。
   - 最后执行折扣、修正、封顶、排序。

输出格式：
{
  "field1": "",
  "field2": 0,
  "field3": [],
  "applied_rules": []
}

只输出 JSON。
```

## 题型模板

### 信息抽取类

适用：PROMPT2、PROMPT3、PROMPT5、PROMPT7、PROMPT8、PROMPT9，以及对应的进阶版本。

关键是防止漏字段、乱造字段、枚举大小写错误。

```text
你是严格的信息抽取器。请从输入文本中抽取字段并输出 JSON。

字段规则：
- name：提取姓名；没有则为 ""。
- phone：只提取标准 11 位手机号；不合法则为 ""。
- date：提取日期并标准化为 YYYY-MM-DD；没有则为 ""。

要求：
- 所有字段都必须出现。
- 不要根据常识猜测缺失字段。
- 输出必须是合法 JSON。
```

### 分类标注类

适用：PROMPT1 情感倾向，以及状态判断、风险标签等枚举选择题。

关键是先定义分类边界，再定义冲突时怎么判。

```text
你是严格的分类器。请将输入归类为指定枚举之一。

分类标准：
- POS：表达满意、喜欢、正面评价。
- NEG：表达不满、抱怨、负面评价；如果一句话正负都有，但主要结论是负面，判 NEG。
- NEU：咨询、事实陈述、无明显情绪。

输出：
{
  "feeling": "POS | NEG | NEU"
}

只输出 JSON。
```

### 规则计算类

适用：PROMPT19-PROMPT35。多数低通过率题都在这里。

关键是把知识库条款改成执行顺序，并要求返回触发规则编号。

```text
你是严格的规则计算器。请按规则逐步计算，最终只输出 JSON。

执行顺序：
1. 先检查红线规则：
   - 如果命中【拒绝条件】，直接输出拒绝结果，金额/额度为 0。
2. 计算基础值：
   - 基础金额 = 【公式】。
3. 应用商品级/项目级规则：
   - 【R.1】...
4. 应用订单级/全局规则：
   - 【R.2】...
5. 应用封顶、取整、保留小数：
   - 最终金额保留【N】位。
6. triggered_rules / applied_rules 按编号升序输出。

输出：
{
  "final_amount": 0,
  "applied_rules": ["R.1", "R.2"]
}

只输出 JSON。
```

### 审批、风控、报销类

适用：信贷、招生、差旅报销、医保报销、航班退款。

关键是先判“一票否决”，再算金额，最后给状态。

```text
你是严格的审批判定器。请按优先级处理：

优先级：
1. 一票否决：命中【作弊/逾期/禁报/无票/超范围】时，状态为 REJECTED，金额为 0。
2. 部分通过：部分项目不合规时，只计算合规部分，状态为 PARTIAL。
3. 全部通过：所有项目合规时，状态为 FULL / APPROVED。

金额计算：
- 每个项目单独按规则计算。
- 不合规项目不计入 final_payout。
- 规则编号按升序输出。

输出：
{
  "approval_status": "FULL | PARTIAL | REJECTED",
  "final_payout": 0,
  "ref_clauses": []
}

只输出 JSON。
```

### 工具调用和参数生成类

适用：PROMPT18 会议安排文本工具调用。

关键是不要让模型“安排会议”，而是让模型把文本变成工具参数。

```text
你是工具参数生成器。请从输入中提取会议安排信息，并生成调用参数 JSON。

步骤：
1. 提取主题、参会人、基础时长、时间信息。
2. 清洗参会人：
   - 内部人员标记 INT。
   - 外部邮箱人员标记 EXT，并去掉邮箱。
3. 计算最终时长：
   - final_duration = base_duration + internal_count * 5 + external_count * 15。
4. 判断是否需要审批：
   - 按题面优先级判断 requires_approval。

输出严格匹配样例 JSON，不要输出解释。
```

## 丢分点清单

- 没有声明“只输出 JSON”，导致模型输出解释或 Markdown。
- 没有把所有字段写进 Schema，导致缺字段或多字段。
- 没有写缺失值默认值，导致模型用常识补全。
- 没有固定枚举大小写，导致 `NEG`、`neg`、`Negative` 混用。
- 没有说明数组排序，导致答案内容对但顺序不稳。
- 没有说明单位换算、保留小数、取整方式。
- 没有写规则优先级，特别是红线、拒绝、封顶、折扣之间的顺序。
- 没有要求返回 `applied_rules` / `triggered_rules`，导致知识库计算题难以对齐判题点。

## 作答策略

1. 基础题（PROMPT1-PROMPT9）把“字段 Schema + 枚举 + 默认值 + 只输出 JSON”写清楚即可。
2. 进阶抽取题（PROMPT10-PROMPT18）要显式写“按步骤处理，但最终不要输出步骤”，否则模型容易漏日期偏移、掩码、单位换算。
3. 知识库计算题（PROMPT19-PROMPT35）要把规则编号当成可执行条款：先列优先级，再列公式，再要求 `applied_rules` / `triggered_rules` 升序输出。
4. 对所有计算题，Prompt 必须写明取整、保留小数、向上取整、拒绝/红线优先级。
5. 题面未定义的信息不要创造新字段；无法判断时按题面默认值处理。
